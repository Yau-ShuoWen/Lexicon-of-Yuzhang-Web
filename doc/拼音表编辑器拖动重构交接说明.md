## 2. 编辑数据的层级

排序对象按以下结构存放：

```text
documentData.sections                 区（section）
  section.rows                        行（代码里的拖动 kind 为 line）
    row.groups                        组（group）
      group.items                      单格（item）
```

界面顶部可选择 `section`、`row`、`group`、`item`、`faq` 五个编辑层级。选中某一层级时，只有该层级的结构可通过指针拖动。行可跨区、组可跨行、单格可跨组；区在 `sections` 中排序。名称编辑、弹窗打开时不启动结构拖动，按在输入框或按钮上也不启动。

## 3. 拖动从按下到松开的流程

代码入口依次为 `pointerDown`、`pointerMove`、`sortTargetAt`、`moveDraggedItem`、`pointerUp` / `finishDrag` / `pointerCancel`。

1. `pointerDown` 记录对象 ID、原数组、原索引、当前数组、指针 ID 和起始坐标，并监听窗口级 `pointermove`、`pointerup`、`pointercancel`。拖动对象由稳定 ID 标识，不依赖 DOM 索引。
2. 鼠标移动超过 **6 px** 后才进入拖动。此时克隆原元素作为跟手预览，保留指针相对元素的抓取位置。预览挂在 `document.body`，不参与命中检测。
3. 原元素继续占据布局位置，但使用 `.sort-dragging` 使其不可见、不接收指针事件。这个位置就是实时落点，不再画黄色框或蓝色虚线框。
4. 鼠标进入另一块的区域时，立即移动数据对象并触发 Vue 更新；其他块让位。鼠标移动的过程中，数据顺序已是当前预览顺序。因此普通松手只结束拖动，不再做一次额外的排序计算。
5. `pointerCancel` 把对象从当前数组移回最初的数组和索引。窗口失焦、页面隐藏、或鼠标已经松开但没有收到 `pointerup` 时，调用 `finishDrag`，保留当时看到的落点并移除跟手预览，防止回到页面后继续黏住鼠标。

`press.currentList` 很关键：跨区、跨行或跨组移动后，不能继续从 `pointerDown` 时的 `press.list` 删除对象。原数组与原索引只用于取消拖动时恢复。

## 4. 目标判定及边界稳定性

- 同一数组中，把鼠标进入的目标项作为换位对象：源在目标前面时插到目标后面，源在目标后面时插到目标前面。无需越过目标中线即可换位。
- 跨数组进入目标项时，插到该项前面；进入有效的空列表区域时可以追加。
- “组”层级在每行最后有 `.group-end-drop` 末尾命中区域。鼠标进入它后直接把组追加到对应 `row.groups` 末尾，解决跨行或在末尾放置困难的问题。容器 `.line-groups-inner` 会伸展以提供可用的末尾空间。
- 动画中的元素会暂时在屏幕上移动。如果直接用 `elementFromPoint` 判定目标，元素可能经过鼠标下方，导致左右反复换位。`sortTargetAt` 因此使用元素**最终布局矩形**：从 `getBoundingClientRect()` 扣除当前动画的 `translate` 位移，并排除源元素和跟手预览。
- 每次实际换位后记录 `lastSwap` 坐标；指针离该点不足 **12 px** 时暂不判定下一个目标。这个小缓冲抑制边界抖动，不改变首次进入目标就换位的行为。

如果将来调整动画类型，尤其是增加缩放或让父元素也带 `transform`，必须重新检查 `sortTargetAt` 的矩形换算；当前计算以平移为前提。

## 5. 让位动画与加号

`moveDraggedItem` 在修改数组前，记录同层级元素的屏幕矩形；Vue 完成 DOM 更新后，再比较新旧位置，使用 Web Animations API 从旧位置平移到新位置，时长 **180 ms**、`ease-out`。连续换位时先取消元素上一次动画，再启动新动画。

加号也会因为卡片让位而改变位置。后续改动给各层级加号标记了 `data-drag-follow` 和稳定的 `data-drag-follow-id`，使它们进入同一批位置快照和位移动画；否则卡片平滑移动而加号瞬间跳走。加号本身不作为可排序项，也不会改变新增函数的行为。

跟手预览采用半透明和 `mix-blend-mode: multiply`，没有白色不透明底与大阴影；原位置没有覆盖目标的遮罩。这是为了解决预览与下层卡片重叠时看不清目标的问题。相关样式位于 `.sort-dragging`、`:global(.drag-preview)`。

## 6. 四层编辑布局与新增位置

| 层级 | 当前布局及新增按钮 |
| --- | --- |
| 区 | 仍按原顺序单列显示；仅在“区”层级把卡片设为容器的约一半宽度，窄屏恢复全宽。原来又宽又扁的底部按钮改为列表末尾一个独立的小加号。 |
| 行 | 保留原行布局；每个区的行列表末尾有同款加号。 |
| 组 | “添加组”从行标题旁移到该行最后一个组后面；拖动时末尾另有命中区域。 |
| 单 | **每一行最后一个组的末尾各有一个**“添加单格”按钮，不是每个组一个，也不是整张表只有一个。新增后可以拖到同一行或其他行的组中。该加号与前一格增加了 `24px` 间距。 |

四类结构新增按钮共用 `.add-structure`：`52 × 52 px`、浅绿色 `#58a869`、白色 SVG 加号；悬停色为 `#4c985c`。按钮通过 `aria-label` 和 `title` 区分“添加区域／行／组／单格”，页面上不额外显示文字。SVG 位于 `src/assets/icons/plus-white.svg`。

区前的彩色色块、行与组的点状手柄，以及拖动时的选中框、目标框均已移除；对应无用样式也已删除。结构元素本身仍可抓取排序。

## 7. 顶部导航和问答

后续改动把顶部编辑层级从四项扩为“区、行、组、单、问答”五项，分别通过 `pinyin-editor/:level` 访问。外观参考词典主导航：浅绿色胶囊底、圆角按钮、平移的浅绿色选中块。这里只参考视觉，没有修改词典导航组件。

选中“问答”时隐藏区／行／组／单的编辑列表。问答列表只渲染 URL 当前语言的富文本预览，点击后在弹窗中编辑题目和解答；弹窗使用独立草稿，关闭时写回。问答通过左侧手柄实时排序，取消拖动时恢复原顺序。保存仍使用原有文档保存流程。

## 8. 子项与解释

单格弹窗打开时默认选中第一个子项，双击子项框编辑名称。拖动子项只改变顺序，不改变选中项或下方解释内容。子项、未归类子项以及解释列表均采用指针拖动和实时让位；解释只从左侧手柄起拖。空子项才显示删除按钮。解释区不再有连接线和外层定位框。问答与解释手柄使用相同的六点图形，新增入口使用绿色方块与白色 SVG 加号。

## 10. 高度不同的卡片反复换位

- **出现原因**：问答预览以及汉字注释的卡片高度会随内容变化。原判定在指针进入目标卡片时立即换位，并仅用换位点周围 12 px 的距离防抖。小卡片向下进入大卡片后，大卡片移到指针上方，但指针仍处在它的较大命中区域内；继续向下超过 12 px 时，就会被判定为反向换位。
- **实际行为**：即使指针匀速向下，大卡片也会在两个位置之间反复上下跳动。数据顺序随每次误判来回变化，而不只是动画抖动。
- **处理方法**：记录上次换位的目标项、指针纵坐标和换位方向。再次命中同一目标时，只有指针沿相反方向越过上次换位点 12 px，才允许换回；继续朝原方向移动则忽略这次命中。命中其他目标仍可正常排序。汉字注释使用同一原则，并按卡片相对位置确定方向，以兼容网格布局。
